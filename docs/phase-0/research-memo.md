# Phase 0 research memo — neuroprivacy

This memo is generated by `research/phase0/render_docs.py` from harness
`results.json` files. Narrative is the template; every quantitative claim is
substituted from those files. Re-run `make research` after changing a harness.

**Safety.** Findings are observations, not legal conclusions, not legal advice,
and not a compliance certification. Phase 0 uses public-style synthetic
policies only. No circumvention. Network observation is gated to
operator-owned devices and is off.

---

## §1 Problem statement

Colorado HB24-1058 and California SB 1223 classify neural data as sensitive
personal information. Consumer neural devices ship with privacy policies that
may or may not name that category, grant deletion, or contradict themselves
with retention language. Auditors currently read those pages by hand.

The people who pay for the gap are consumers who cannot exercise deletion,
vendors who do not know whether a clause change created a conflict, and
researchers who cannot tell a generic "device data" paragraph from an explicit
neural-data grant. Scraping authenticated portals or bypassing device
protections is out of scope.

This repo extracts typed, span-cited fields from public policy HTML and
scores them with deterministic rules against encoded CO and CA provisions.
Network capture, if it ever runs, is optional, operator-owned, and opt-in.

## §2 Prior art

| Tool | What it does | Gap |
| --- | --- | --- |
| [IAPP / state tracker writeups](https://iapp.org/) | Human summaries of HB24-1058 and SB 1223 | Not an extractor; not reproducible on a vendor page |
| Vendor privacy portals | The policies themselves | No span-level schema; no drift diff |
| Generic CCPA scanners | Keyword checks for "sell" / "share" | Miss neural-as-SPI; miss generic device-data cover |
| Wayback Machine | Dated HTML snapshots | No statutory scoring |
| Mobile traffic interceptors | Packet capture | Circumvention risk; this repo gates capture and keeps it off |

Something already "solves" reading a privacy policy: a lawyer does. Another
tool is still worth building because (1) neural data is a new SPI category
and generic scanners do not look for it, (2) contradiction (deletion vs
retention) is a first-class INDETERMINATE, and (3) drift across snapshots is
measurable. The product is an observation trail, not a certification.

## §4 Technical selection

Each choice below is expensive to reverse. Options, criterion, measurement,
decision.

### 4.1 Policy extractor

Options: keyword baseline; deterministic span rules; live LLM with pydantic
and span citations; rules plus a committed response cache.

Criterion: mean per-field F1 versus hand labels, Cohen's kappa versus the
keyword baseline, and gold-versus-rater-2 kappa. Ship the richer extractor
if mean F1 ≥ 0.80 and inter-rater kappa ≥ 0.60.

Measurement: `research/phase0/extraction_accuracy/` (n=20 documents).

Live LLM quality and API RTT: **unmeasured**. The measurement that would

does not call a live API.

### 4.2 Statutory scoring

Options: LLM judge; lawyer rubric; deterministic rules over extracted fields.

Criterion: scoring must be replayable in CI with no secrets and must emit
INDETERMINATE on contradiction rather than a forced label.

Measurement: unit tests on vendor-a / vendor-b / vendor-c plus
`statute_coverage` checkability.

Decision: **deterministic rules in `src/neuroprivacy/scoring.py`**. An LLM
judge is `# TODO(v2):` and would need a hold-out rubric.

### 4.3 Scope: policy text vs network observation

Options: policy-only; policy plus always-on capture; policy plus gated
operator-owned capture.

Criterion: fraction of encoded CO/CA provisions that are machine-checkable
from policy text alone.

Measurement: `research/phase0/statute_coverage/` (22 clauses).

Policy-text fraction = 14/22 = 0.636.

Decision: **14/22 = 0.636 of encoded provisions are machine-checkable from policy text. Phase 2 should center on extraction + deterministic scoring. Network capture stays optional.**

### 4.4 Monitoring cadence

Options: weekly, monthly, quarterly, on-demand.

Criterion: observed month-to-month change rate on 5 synthetic vendors.

Measurement: `research/phase0/policy_drift/` (60 snapshots).

Change rate = 16/55 = 0.291. Cadence = monthly.

Decision: **Observed change rate 16/55 = 0.291. Recommended monitoring cadence: monthly.**

Live Wayback change rate on real vendors: **unmeasured**.

## §5 Evaluation design

Hold-out (Phase 3, not run here): 20 current public consumer-neural-device
policies, fetched without authentication, with two independent human labels.

Metrics, declared before any live model is built:

- Per-field precision/recall/F1 versus hand labels
- Cohen's kappa versus keyword baseline
- Cohen's kappa between two labeling passes
- Status accuracy (COMPLIANT / GAP / INDETERMINATE)
- Statute coverage fraction
- Policy change rate

Split: the 20 snippets are the entire Phase 0 set. Seed is unused. No
random reshuffle in CI.

**Failure condition (written before the answer):** the project fails if, on
the Phase 3 public-policy hold-out, mean field F1 does not beat the Phase 0
mean field F1 (1.000) by any margin **or** if inter-rater kappa falls
below 0.60 **or** if any INDETERMINATE gold document is emitted as COMPLIANT.

## §6 Cost and scale model

Phase 0 extraction is local CPU: regular expressions over short HTML. Live
LLM cost is **unmeasured** (no live calls). Numbers:

- Documents extracted in extraction_accuracy: 20
- Mean field F1: 1.000
- Status accuracy: 1.000
- Live LLM USD / document: unmeasured
- API RTT: unmeasured
- Drift snapshots scored: 60
- Observed month-to-month change rate: 0.291

Unmeasured: lawyer-hours saved, live Wayback ingest wall-clock, device-capture
storage. The measurement that would settle ingest cost is a timed fetch of 20
public policies on a 4-core machine, recorded as seconds and peak RSS, with
robots.txt honored.

| Statute summaries drift from session law | Scope | Citations are included; re-encode before Phase 2 scoring. |
| LLM cache treated as a live model | Technical | Cache is keyed by prompt hash; misses use rules; no API client. |
